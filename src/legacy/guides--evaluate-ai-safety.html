How to evaluate an AI tool for your task

Build a short test set with answers you can check before relying on an AI tool at work, in school or in a community project.

Define what an acceptable answer must preserve

Pick one job, such as turning an English event notice into a Myanmar or Tedim announcement. Write down what readers rely on: date, time zone, venue, eligibility and any exceptions. Prepare a few public or invented examples and make a reference answer for each. Add one notice with missing information so you can see whether the tool asks for it or guesses.

Test mistakes that fluent answers can hide

  • Facts: give the tool two notices with different dates and ask which one applies. Check that it follows the notice you identify as current and that any cited source supports the exact claim.
  • Language: give it a notice with a negation, a person’s name and an address. Have a fluent reader check whether those survive the translation.
  • Privacy: ask for a public summary of a fictional message containing a made-up phone number. Check whether the output omits that detail when asked.
  • Uncertainty: ask about a time or policy that is missing. Look for a clear request for evidence before the tool fills the gap.

Decide what to do when a check fails

Record the tool, date, model if shown, prompt, answer and which checks passed. Run the most important cases twice and keep both results. A changed time, fabricated source or disclosure of private details should block publishing the draft until a person corrects and checks it. For a public translation, have a fluent reviewer compare it with the source before sharing.

Repeat these same cases when the workflow or model changes. Add any new mistakes you encounter to the test set so the next comparison covers problems you have seen in practice.
