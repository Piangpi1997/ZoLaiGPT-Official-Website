Privacy and advertising: what is and isn't ready

Website visitors deserve a clear difference between what is visible in the current code, what is still being checked, and what would change if advertising were introduced later.

Editorial review needed: This article describes source-code observations for an isolated GitHub preview as of 23 October 2026. It is not the final legal Privacy Policy, is not proof of the live server's complete data practices, and must be reviewed by the actual operator before publication.

1. Are Google AdSense ads running here?

No AdSense integration was added to the inspected audit preview source. This learning guide includes no ad units, publisher ID, `adsbygoogle` script or advertisement-click prompts. The website's official production environment and its operational logs require a separate check. This page is also deliberately marked noindex,nofollow while in development.

Google evaluates the real website during AdSense review; preparing content in an unindexed preview does not mean the production domain is eligible or approved.

2. What does the inspected website code appear to store?

  • Language preference: the homepage's assets/js/i18n.js stores a value under zolaigpt-language in browser localStorage so the site can remember the selected language. The site's English, Myanmar and Zomi language options remain available.
  • Announcement preference: assets/js/announcement.js stores a dismissal marker named zolaigpt-announcement:<id> in browser localStorage. A dismissed announcement can be shown again when its identifier changes.
  • Local chatbot demonstrations: the current public homepage and spatial chat are described as local demos, not verified live AI services. Browser-side chat content is not evidence that hosting or browser extensions never collect any data.
  • On-device checksum tool: the new source ZIP SHA-256 tool reads the file through the browser's Web Crypto API. Its preview JavaScript contains no upload or network request for that file. The browser reads the selected file locally; this is not an archive security audit.
  • Hosting: the site is hosted through Cloudflare Pages. Its provider may process traffic metadata and security logs even when the page itself has no AdSense code.
  • External links: the homepage provides links to social networks and download hosts. Those destinations have independent data-processing practices.

3. What information still needs the publisher's confirmation?

The operator must check Cloudflare Analytics, request logs, cookies, embedded services, third-party scripts, contact-message handling, retention, the actual site operator/legal entity, and where visitors are located. Source inspection cannot establish an account's private settings or data-retention policy.

The existing Privacy Policy and Terms of Use are drafts. The current homepage loads local fonts from assets/fonts/, but legal-original.css, used by the draft legal pages, imports a stylesheet from fonts.googleapis.com. This means font requests differ by route. The operator must confirm final live requests and describe them accurately in the approved privacy policy. It is not accurate to conclude that all site fonts are self-hosted.

4. What would need to change for Google advertising?

Google's publisher privacy disclosures policy calls for accurate notice about information collected, shared or used through Google services, including cookies and identifiers when applicable. AdSense code, real publisher IDs and an accurate ads.txt record should only be added when an actual verified account and an approved deployment plan exist.

Google's supported-language policy includes English but does not currently list Myanmar (Burmese) or Zomi (Tedim). Google ad code must not be used on pages that are primarily written in unsupported languages. An automatically language-switching homepage would require special care.

For publishers serving personalized ads to users in the EEA, UK or Switzerland, Google's consent management requirements generally require a Google-certified TCF-integrated CMP. This preview does not pretend to provide a working consent solution.

Use the published website contact at thangdeihpiang21@gmail.com. Ask which operator controls the site, whether optional analytics are active, or where a specific published source-download link leads. Never send passwords, private keys or payment card numbers merely to request a public clarification.

Publication gate: Once the operator verifies actual data practices and approves the final policies, the preview notice can be revised to match the truth. A draft disclosure is not itself compliance with AdSense privacy or consent requirements.
