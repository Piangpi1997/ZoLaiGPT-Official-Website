How to verify downloads with SHA-256

Learn to calculate a file checksum locally on Android, Windows, macOS or Linux and compare it with an independently verified reference from the publisher.

How to use this guide: This educational text was prepared with AI assistance and reviewed against the linked reference materials. It is not a software security certification, an approved translation, or a substitute for checking the current official instructions. Report corrections by email.

What is SHA-256?

SHA-256 is a fingerprint of a file. A 64-character digest helps you compare downloaded bytes against a trusted reference. A matching hash does not establish that a file is safe, malware-free, or produced by a legitimate developer.

Desktop commands for larger files

Substitute your actual filename for download.zip.

Windows PowerShell

Get-FileHash -Algorithm SHA256 "download.zip"

macOS

shasum -a 256 download.zip

Linux

sha256sum download.zip

Worked example (illustrative)

This example uses plain text so you can reproduce it exactly. The SHA-256 of the eleven characters hello world — typed with no trailing newline — is:

b94d27b9934d3e08a52e52d7da7dabfac484efe37a5380ee9088f7ace2efcde9

Save a plain-text file containing exactly hello world and nothing else (do not press Enter at the end), then calculate its hash with the tool above or a desktop command: you should get the same value. This is a teaching example only. It is not the checksum of any real download, and a real publisher's checksum must always be copied from that publisher's official page.

Step-by-step: verifying a downloaded file

  1. Download the file from the publisher's official website or official release page, not from a file-sharing mirror.
  2. Find the SHA-256 checksum the publisher provides for that exact file and version, on the official download or release-notes page. Treat a checksum pasted into a random forum post or chat message as unverified.
  3. Calculate the hash of the file you actually downloaded: the browser tool above for files up to 32 MiB, or the desktop commands for larger files. Hash the downloaded archive itself, not the files extracted from it.
  4. Compare all 64 characters. Hexadecimal letters may be upper- or lower-case, and spaces used for grouping can be ignored. If you paste the reference checksum into the tool above, it compares the values for you.
  5. If the values match exactly, read the next sections before using the file. If they differ, do not open, install or build from the file — work through the troubleshooting list below instead.

Common mistakes and troubleshooting

  • Hashing the wrong file: an older download, a renamed copy, or the extracted folder instead of the original archive.
  • Wrong reference: comparing against the checksum of a different version, platform build or file format.
  • Truncated checksum: a SHA-256 digest is always exactly 64 hexadecimal characters; if yours is shorter, the copy was incomplete.
  • Extra bytes in text examples: a trailing newline changes the hash, because the contents must match byte for byte.
  • Size limit: if the browser tool reports the file is too large, that is a tool limit, not a problem with the file — use the desktop commands instead.
  • Still mismatched after re-downloading from the official source? Stop and contact the publisher through their official channels; do not search for a "fixed" copy elsewhere.

How to interpret the result

If hashes differ, recheck your file and the publisher's source. Do not execute it until the difference is resolved. Even matching hashes do not prove a download is trustworthy. Review the source, software signatures and permissions.

What a matching checksum does — and does not — prove

A match proves consistency, not safety. It shows that the bytes you downloaded are identical to the bytes the checksum was calculated from, so the file was not corrupted or quietly replaced after the checksum was published. It does not show that the software is safe, honest, or genuinely from the named publisher: if someone replaced both the download and the checksum on the same page, the pair would still match. A checksum is therefore only as trustworthy as the page you copied it from — take it over HTTPS from the publisher's official source, and prefer distribution methods with their own signatures where they exist, such as signed app-store releases.
